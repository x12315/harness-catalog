# 浏览器工作模式

本 Skill 决定如何与人配合；工具执行、支持限制与切换保护以所用 `agent-browser skills get core` 的配套内容为准，避免在此再造会话管理器。使用前同时读 `agent-browser` Skill 并运行其要求的 core发现；具体参数以当前实际安装的CLI为准，不凭fork源码、版本号或一次文档更新假定能力已部署。不绑定某个项目、网站、端口或会话名，不修改第三方安装内容。

## 先决定模式，不先开窗口

按以下顺序判断；用户显式选择优先于任务推断，适用范围按用户原意，不把一次偏好变成全局设置。

1. **沿用同一任务已有约定**：正在共同操作的页面继续协作；已约定独立完成的任务继续后台。仅打开着一个可见浏览器，不等于用户要求后续所有任务都协作。
2. **意图明确就自动选择，不反复问**：
   - 协作：用户说“一起看”“我看着你操作”“让我接手”“先展示我再决定”，明确要打开可操作页面给自己看，或完成这一步确实依赖用户在同页观察/操作。使用可见、人可接手的浏览器。
   - 后台：用户说“你自己查/处理”“后台完成”“不需要打开给我看”，或普通资料查询、抓取、比对、导出、独立网页测试，没有共同操作的需要。使用独立 headless 会话。
3. **可以合理推断时自行决定**：采用上述默认，必要时一句话告知“我在后台查询”或“我打开可见页面，我们一起操作”，不要让用户先学工具参数。截图、浏览器自动化或任务复杂本身都不意味着协作；“看一下”也不自动意味着开可见窗口。
4. **实质歧义才问**：例如“打开这个看看”在上下文中既可能是 agent 读内容，也可能是用户要共同操作；现有标签有未保存内容，且是否复用会影响用户工作。问一句：**“这次要打开可见页面一起操作，还是我在后台完成后给你结果？”** 确定模式前不擅自附着个人浏览器、抢占页面或弹窗。与选择无关的只读准备可以继续。

“完成后告诉我”通常适合独立执行，但不自动授予登录、提交、发送、付款、设备动作等权限。**模式不是操作授权。** 同样，协作模式不要求每次普通点击都另请批准。

## 两种模式真正分开

| | 可见人机协作 | 独立后台 |
|---|---|---|
| 浏览器 | 本机可见窗口；或用户实际能访问并操作的共享浏览器 | headless，用户无需持续观看 |
| 会话 | 专用于当前协作任务，用户能识别与接手 | 专用于当前独立任务，不借用协作页面 |
| 页面操作 | 双方交接，避免同时点击；保留用户正在看的标签 | agent在自己的会话内完成；可并行但不共享页面控制 |
| 结束 | 告知当前页面、完成情况，按约定保留；不擅自关闭共享窗口 | 保存结果后只清理自己创建、已无用途的会话 |

至少按 **模式 + 任务/拥有者** 隔离会话；`collab-*` / `bg-*` 可作为前缀，但名字不是隔离或可见性的证据。不同名字若附着同一个 CDP 浏览器，仍会共享标签、认证等；不要把它当成独立浏览器。子代理不能同时操纵同一共享会话。

复用当前任务已有会话前先查看 session/tab 信息，确认实际CLI路径、会话归属、启动模式与目标。升级时保留旧任务原用的二进制与窗口，不让新CLI自动迁移活跃会话；新任务可用独立副本及新命名会话。没有现成会话时复用 CLI 的 session-id 能力并使用任务级名字；不使用默认匿名 session。

### 优先调用原生工作模式

先通过当前CLI帮助和配套core技能确认是否提供 `--work-mode collaboration|background`。支持时优先使用原生接口，不自行模拟它的模式锁定、冲突判定或关闭重开流程：

```bash
# 两个不同会话；按本次选定模式只执行其中一种，不同时启动。
agent-browser --session "$COLLAB_SESSION" --work-mode collaboration open "$URL"
agent-browser --session "$BACKGROUND_SESSION" --work-mode background open "$URL"
```

后续可省略模式，由工具沿用会话策略；用原生session info/lifecycle核对 `workMode` 与 `effectiveMode`。支持该协议的工具会先核验daemon的 `workModePolicyVersion: 1`，版本字符串相同不等于能力相同；不要在Skill里重复实现这套握手。工具拒绝不兼容复用、附着或重启时，先核对现场，不通过去掉模式、换低层入口或擅自close来绕过。原生接口的外部浏览器、引擎、插件及chat等支持边界以该二进制配套说明为准。语义选择由agent负责，工具不自动猜用户意图，也不证明人确实能看见屏幕。

### 旧CLI兼容调用

当前安装确实不支持原生接口时，保持两个独立任务会话并显式选择 `--headed true` / `--headed false`；不能宣称具备原生冲突拒绝或自动重启保护。这个回退只适用于新建、由自己拥有且模式已核验的会话，不用于绕过原生拒绝；有未保存状态或未知提交的现有会话不能盲目切换。不自动安装fork、替换全局CLI或迁移活跃daemon。

显式 `--headed false` 避免用户/项目配置的 headed 默认污染后台模式；同一会话后续调用保持一致的模式和配置，不让下一条命令又继承相反的全局默认。不要为了给已有会话加或改启动参数而直接重开：参数变化可能重启浏览器、丢失页面或未保存状态。查看实际启动回执，协作还需确认用户确实能看到/操作；headless截图、会话名字、只存在于远端容器的 headed 窗口都不等于已实现协作。缺少可见/共享能力时说明缺口，询问替代方式，不静默降为后台。

默认不 `--auto-connect`、不连接用户个人浏览器、不加载个人 profile。只有明确获准复用指定窗口/身份时才附着；共享 CDP 场景按 CLI 文档使用 tab 绑定，不能抢无关标签。不要把后台任务的 cookie、登录态复制到协作会话或反向迁移；如确需迁移，先说明范围并取得授权，使用原生认证/状态存储，不入库。

## 交接与切换

- 同一协作页面上，一方操作时另一方暂停点击。用户说“我来操作”就停止自动交互；用户明确交回或说“好了/摆好了，继续”才恢复。恢复先重新读取当前标签、URL、DOM与任务状态；旧元素引用不能当作当前页面事实。只读观察可以继续，除非用户要求完全暂停。
- 任务意图变化时可以切换模式，不要求用户必须使用特定术语。先核对正在执行的提交及副作用，保存必要结果、当前页和待办；不关闭、刷新、重启或移动仍有未知提交/未保存状态的页面。复用还是新建按实际能力决定，不盲目把同一 session 由 headless 改成 headed。
- 后台任务临时需要人工登录/验证码，不代表整个后续任务都改为协作；先说明需人工处理的那一步，按授权安排可见交接，完成后恢复原独立方式。不能绕过验证码或擅自迁移登录态。
- 独立后台是浏览器交互方式，**不等于任务已脱离 agent 持续运行**。跨当前轮次继续执行及完成通知，按可用的 `background-task-notify` 和既有后台设施安排；没有安排就不能承诺“我会自动通知”。
- 只关闭明确归属于自己、已完成且无需保留的后台资源；不 `close --all`，不清理别的agent或用户的会话。用户要求保留时尊重该范围，也明确浏览器会话不是永久存档。

## 交付

说明实际使用的模式、完成了什么、用户是否需要接手。没有打开可见页面不能说“你现在能看见”；只准备好参数不能说协作已验证。内容规则与工具行为分别验证，参见 [决策校准用例](evals.md)。
