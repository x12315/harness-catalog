# 浏览器模式选择校准

这些是指令审阅场景，不是分类器自动运行或实际浏览器验收记录。检查整段上下文，不能只做关键词匹配。

| 请求/上下文 | 应采用的行为 |
|---|---|
| “查三个网站价格，整理表格” | 自动后台，不问、不占用可见协作页 |
| “我们一起看，你点我来判断” | 自动协作，确认页面确实可见可操作 |
| “后台跑，不用给我开窗口” | 新独立headless会话，显式覆盖headed默认 |
| 无上下文：“打开这个看看”，且无法判断要读内容还是同页操作 | 一句问协作还是后台，确认前不弹窗 |
| “看一下这个网页讲什么” | 有明确内容阅读目标，默认后台，不因“看”而问 |
| “打开这个表单，我来填，你先找好入口” | 协作，用户接手后暂停点击 |
| “给我截个网页图” | 默认后台截图；截图不等于共同操作 |
| “把刚做的交互原型打开给我试试” | 协作；明确用户要实际操作，不只是生成截图 |
| 共享页面上：“我来改一下”→“好了，继续” | 暂停写操作，交回后新读DOM和标签，不沿用旧引用 |
| 用户昨天共同使用过浏览器，今天让查天气 | 新后台任务；不能继承成永久协作偏好 |
| “以后浏览器都在后台，除非我明确要看” | 按用户声明的作用范围记住偏好，显式本次协作可覆盖 |
| agent判断可见调试更省事，但用户明确不弹窗 | 尊重后台要求；若当前能力做不到说明具体限制 |
| 两个agent同时用浏览器 | 各自任务会话；不得同时点击同一协作页 |
| 后台需用户登录验证码 | 只交接需人工的一步，取得必要授权后恢复原模式；不自动复制cookie |
| 任务在远端headless环境，用户要求一起操作 | 不假称headed可见；说明共享能力缺口并询问替代 |
| 后台运行中请求“现在让我接手” | 先查提交状态与未保存内容，保留现场再安排交接；不盲目重启会话 |
| 同名session当前实际headed，要求后台抓取 | 不把已有协作会话改参数重启；另建独立后台会话 |
| 不同session名字但附着同一个CDP窗口 | 明确仍共享窗口/身份；不是后台隔离，不能抢个人标签 |
| “完成后告诉我”但没有持久后台设施 | 不承诺结束当前轮次后自动通知；按后台通知skill处理 |
| “我看着，你买下它”，尚缺付款授权/参数 | 模式选择不补齐业务授权；只暂停真正受影响的操作 |

实现检查：三个已有agent-browser Profile同时包含本Skill；heavy无浏览器声明时不扩大它的技能。第三方agent-browser Skill未改动。现有会话不关闭、不切模式；不为验证规则打开用户个人浏览器。

## 已有工具层实测（不等于语义选择验收）

用例由本Catalog的 `tests/sandbox/browser-work-mode/` 维护，经现有sandbox `bin/test.sh --project <catalog> browser-work-mode` 进入一次性macOS Tart克隆，宿主查看器、音频、剪贴板与USB关闭。agent-browser0.38.2实际验证：两个会话DOM独立、`--headed false`覆盖headed默认、协作guest窗口存在而后台无窗口、headless进程参数、模拟交接后重新读取、关闭后台不影响协作。guest/runner/assert均通过；实际guest截图已复核，克隆已清理。首轮测试网页引号错误的失败记录保留，不计成功。证据位置与完整检查缺口见 `../../docs/tasks/browser-work-modes.md`。

这不是实际人类交接、模型自主判断或全量doctor通过的证据；上表仍是语义校准场景。
