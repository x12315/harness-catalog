# 本地产物交付

- 使用依赖 Pi `file-links` 的链接前，确认当前会话实际加载扩展。配套 Pi/Profile 的 `/reload` 静态准备、重解析所有受管计划（包括内置 default）并原生刷新一次，不逐次完整 doctor；默认工具基线按实际有效选择更新并保留手动禁用项。开发验收仍用 `/harness apply` 的完整 gate。以 `/harness status`、`/harness help` 判断会话能力，不用相同版本号推断包内容。
- 旧进程不能靠 reload 获得新 Pi/Profile；安装配套包后须从外部终端通过 `pi-h` 正常重启一次。Engine 扩展编辑仍可 reload，Pi/Profile 源码修改须新 build/install 并启动新进程，不自动改变不可变包；分发维护见 Engine `docs/local-distribution.md`，先用 `harness status --json` 定位 Engine。普通 PATH `pi` 不被替换，已选择但损坏的受管包不自动回退。
- 用页脚和 `/profile status` 核对当前资源；磁盘回执、新进程、虚拟机验收不能替代当前会话确认。尚未加载时，使用用户已确认有效的可见短路径回退，不把依赖新扩展的蓝色链接当作可用入口。
- 与声明无关的产物编辑不需要 reload。默认启动方案只影响下次启动；模型和 thinking 按原生保存动作生效。CLI `harness refresh` 仅磁盘静态准备，不安装、联网、请求模型或注入会话；CLI apply 另做完整 verify。依赖安装仍需授权的官方流程及必要重启。
- 先确认文件存在，使用简短、描述性的 Markdown 标签，目标填写完整、真实的绝对本地路径；路径含空格时用 `<…>` 包住目标。不使用 `~`、相对链接或虚构路径，通常将 URL 编码交给扩展处理。
- Pi 的 `file-links` 扩展在原生 Markdown 渲染前将目标转换为编码后的文件 URL，通过原生 OSC 8 输出；保留系统默认应用，不指定或修改文件关联。
- 需要行列提示时可使用 `:123[:45]` 后缀；是否定位取决于终端和默认编辑器，打开成功不等于已验证具体行列。真实文件名若以数字冒号后缀结尾，为避免歧义，可例外使用标准库生成的明确编码文件 URL。
- 直接交付原文件；只有确实需要排版或交互展示时才生成 HTML。默认不创建软链接；仅在用户明确需要且已确认旧 renderer 的兼容问题时，可用软链接作可选回退，并说明实际文件位置。
- 默认只提供链接，不自动打开宿主机窗口。只有用户明确要求打开时，才可打开当前任务的实际产物；授权不包含无关文件或测试窗口。
- 点击、打开和默认应用验证仅在现有 `~/Desktop/agent-harness-sandbox` 虚拟机内进行。虚拟机不可用时报告验证缺口，不回退到宿主机测试。
