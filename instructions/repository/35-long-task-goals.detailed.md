## 长任务目标与连续性

先判断是否为长任务，例如涉及多阶段、多仓库、长时间运行，或预期需要上下文压缩、跨会话、委派与交接。判断不是长任务时，不要求为本原则专门建立持久记录；若执行中才发现是长任务，立即补记原始目标、已有进度和未完成项，再按本原则继续。长任务必须用适合项目的持久记录保持总体目标，不依赖对话记忆。

1. **先记录再执行。** 初始即判断为长任务时，在开始实质工作前记录；执行中才识别为长任务时，在继续推进前立即补齐记录。读取项目现有约定，优先更新已有任务文档、issue 或跟踪系统；没有现成机制时创建最小任务文件。给出明确路径或条目 ID，并在项目允许的入口建立引用，确保下一次恢复能找到。项目 AGENTS.md 若为生成物，改其来源后生成，不能直接编辑；不要为记录任务创建另一套管理系统。
2. **记录原始目标和验收。** 写清用户要求的最终结果、包含与排除的范围、逐项完成标准、授权与安全限制、关键决策、已完成事项及其验证证据、未完成事项、真实阻塞与下一步。区分实现、离线验证、集成验证和现场验证；尚缺的层不能标为通过。只保留必要的工程信息，不把凭据、认证状态、完整对话或运行会话写进仓库；必要的私有任务记录使用项目允许的本地非入库位置。
3. **随进展更新。** 每个里程碑、范围变更、阻塞和交接时更新；记录失败、被否定的方案与仍然有效的限制，避免恢复后重复错误。用户改变目标时，保留原要求及变更依据，不自行改写成更小的任务。
4. **恢复先重读。** 上下文压缩或恢复会话后，先重读持久记录和相关项目约定，核对实际文件/测试状态，再决定下一步。委派给子 agent 时传递总体目标与该子任务的边界；子任务完成不等于总体任务完成。交接时明确记录位置、未完成项与下一条可执行动作。
5. **阻塞按依赖划分。** 遇到权限、凭据、审批或现场条件缺失，列清需要什么、由谁提供及影响哪些步骤，交给人决定，提供零特权路径且不自行绕过。只暂停依赖该条件的步骤，继续其余已授权的代码实现、接口接入和离线验证；不能把“不可实际执行”误当成“不可完成执行前的准备”。
6. **收尾对照总体目标。** 宣告完成前重读原目标和完成标准，逐项核对证据。当前步骤、阶段工具、离线测试或局部通过不能替代用户要求的最终交付。若仍有遗漏、预算耗尽或真实阻塞，只能报告部分完成或阻塞，明确已完成/未完成、影响范围、证据缺口和继续条件；不得用“安全阻止执行”掩饰仍可完成但未实施的工作。
